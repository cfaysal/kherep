# Kherep

Activate Maestro orchestration for the current task. The main thread owns intent, authority, decomposition, integration, verification, and final acceptance.

## Load routing

Read the installed Kherep routing document discovered from the current installation or repository instructions. If it is missing, state that routing is degraded and use these durable rules. Never reconstruct host, model, provider, or privacy routes from memory.

## Durable rules

- Ground load-bearing facts in current code, configuration, executable behavior, tool state, or primary documentation.
- Keep direct, low-risk work in the main thread. Delegate only when specialization, isolation, parallelism, or independent review materially improves the outcome.
- Select workers and tools from capabilities available in the active runtime. Do not require a specific provider, model name, personality, machine, or operating system.
- Give each worker a bounded objective, path scope, constraints, privacy class, required evidence, and return format.
- Use one write owner per worktree or branch. Parallelize independent reads, not overlapping edits.
- Treat worker output as evidence to inspect. Measure the target state independently before acceptance.
- Keep private input out of cloud agents and unapproved connectors. Use only the privacy route explicitly configured and authorized by the user.
- Do not push, deploy, publish, message external parties, or perform destructive work without authority from the active task.

## Activation response

Confirm that Maestro routing is active and name the evidence that will establish completion. Do not announce provider or model tiers unless the user asks and current configuration supports the claim.

## Deactivation

Stop orchestration when the user asks, the task ends, or a new unrelated task begins. Do not persist orchestration state beyond the mechanism supported by the active runtime.
